Seven plain-English steps for a non-technical audience, running on this server.

Function surface

One mark per function in the aidb schema, coloured by area. Rounded marks are aggregates. Select a mark to open that function.

 

Functions

Signatures come from pg_get_function_arguments(), so defaults and named parameters match what the server actually accepts. Open a function for its parameters, a ready-to-edit call, and its source.

Tables & views

Catalog tables and views in the aidb schema. Row counts are planner estimates until you browse. Values stored under keys that look like credentials are replaced before they reach this page.

Types

Enums tell you the valid values for parameters such as auto_processing or distance_operator.

Settings

Every aidb.* GUC visible to this session. Rows where the current value differs from the built-in default are marked.

Live objects

What has actually been created on this server, via aidb's own listing functions. Each one runs on its own, so a missing function on your build shows up as a note rather than breaking the page.

SQL editor

New to the SQL console? Read this first
  1. Get a query into the box below. Pick one of the buttons under the box (list_models(), Providers, …), or open one from a Showcase step with Open in SQL console, or type or paste your own.
  2. Press Run, or Ctrl+Enter (⌘+Enter on a Mac). If you have selected part of the text, only the selection runs; otherwise everything runs. Put each query on its own and end it with a semicolon.
  3. Read the result under the editor. Each query gets its own table. Click any cell to read a long value in a side panel. Grid shows tables; psql text shows exactly what a terminal would print.
  4. It is read-only. Nothing is changed unless you tick Allow writes. A few AIDB commands, such as asking an agent a question, record a conversation and need that tick.
  5. Errors are normal and harmless. Red text under the editor says what went wrong, and The SQL behind this panels in the Showcase show working examples.

Runs through your psql. Each statement gets its own result; psql describe commands such as \df aidb.* or \d aidb.models work on their own line. Read-only unless you allow writes. Model functions (encode_text, generate_text) still call the model.
